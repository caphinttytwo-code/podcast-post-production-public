# Explicit target-runtime handoff

Branch ID: `target-runtime`. Enter only when the user has requested structural/runtime selection and approved the exact selection and its stated content losses. It is separate from `rigorous-explainer` and `casual-non-rigorous`.

- Read [planning handoff](../../editorial-plan/references/handoff.md). Match source identities, clocks, plan revision, choices and operation scope. A planning checker is not an approval or executable EDL.
- Approved whole-theme or case removals may lose information explicitly identified in the approved plan. Do not reject that authorized scope merely because rigorous preservation would normally retain it. No other unique claim, qualification, contrast, story dependency or emotional function may be silently lost.
- Reuse [shared decision rules](editorial-decision-rules.md) for retained speech, mechanical defects, pause work and post-edit sentence/logic/pacing/persona checks. Macro removals still need complete boundaries and resolved callbacks.
- Keep whole-block moves and fine editing distinct. An approved grouped rerecord remains grouped; do not remove internal words without the specific fine-edit authority.
- For solo execution, use existing EDL v3 with `branch: target-runtime`, the existing staged transcript provenance, approved-only cuts and pending review candidates. Add planning lineage under `planning_basis` (plan path/hash, revision, item IDs and review-record paths/hashes). This is an additive annotation; the legacy renderer does not authenticate its human authority. The agent must read those records before execution.
- For synchronized stems, keep the existing multitrack project/plan formats, approved decisions and integer-frame compiler. Record the planning lineage alongside them; do not feed planning JSON directly to the compiler or relax alignment checks.
- Once the authorized macro edit is made, refresh the staged transcript before further semantic or pause edits. Previously approved items are reused only while source, version, scope and choices match; any new losses need review.
- Actual output timing, local fades, PCM preservation, post-edit content verification and human listening remain the existing execution module's responsibility. Do not present a projected transcript as actual new ASR.
